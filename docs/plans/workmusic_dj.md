# 미디어 분석·스마트 DJ 구현 계획

## 구현 상태

- macOS ARM64의 범용 분석 서비스, 실제 1곡 검증, 마감이즈커밍 분석 UI와 수동 구간 저장을
  완료했다.
- 두 곡의 저장된 수동 구간이 모두 유효하면 계산된 시각에 다음 곡을 시작한다. 수동값이
  없거나 잘못되면 기존 fixed seamless를 그대로 사용한다.
- detected 결과는 현재 편집 참고용이다. detected 기반 자동 전환·추천·장르 보정은 후속이다.
- 최대 100곡 단위의 SQLite batch와 Lab 전곡 분석 진행·중단·재개 UI를 구현했다. 첫 5곡
  실측에서는 최신 cache 2곡을 포함해 4곡 성공, YouTube 다운로드 1곡 실패를 확인했다.
- Ubuntu ARM64 배포 자료는 준비됐지만 오라클 A1 인스턴스 가용 용량이 확보되지 않아 실제
  배포는 대기 중이다.

## 상태

전체 프로젝트 리팩토링과 Apple Silicon Mac의 로컬 `media-analysis-service` 구현은 끝났다.
범용 A1 서버는 Tokyo AD-1 용량 부족으로 생성 대기 중이며, 서버 생성 재시도와 배포는 별도
대화의 승인된 작업에서만 관리한다. A1 생성 후에는 현재 로컬에서 검증한 동일 코드를 Ubuntu
ARM64 서버에 배포한다.

## 로컬 우선 개발 결정

### 확인된 환경

- 개발 Mac은 `arm64`, macOS 26.5.1이다.
- 목표 오라클 A1 서버도 ARM64이며 운영체제는 Ubuntu 24.04다.
- CPU 구조는 같지만 운영체제가 다르므로 macOS 전용 API와 절대 경로를 핵심 코드에 넣지
  않는다.

### 새 로컬 프로젝트

```text
/Users/bacbaqui/Desktop/code/media-analysis-service
```

- 프로젝트 이름과 서버 경로에는 `노동요`나 `workmusic`을 사용하지 않는다.
- 음악 분석을 첫 사용처로 삼되 이후 음성·영상 분석 작업도 추가할 수 있는 범용 작업 API로
  만든다.
- 마감이즈커밍 저장 데이터와 UI는 기존 저장소에 두고 다운로드·변환·분석·작업 큐만 새
  서비스가 맡는다.

### 환경별 차이

| 항목      | 로컬 개발                 | 오라클 운영                 |
| --------- | ------------------------- | --------------------------- |
| 주소      | `http://127.0.0.1:<port>` | `https://<analysis-domain>` |
| CPU       | Apple Silicon ARM64       | Ampere A1 ARM64             |
| 운영체제  | macOS                     | Ubuntu 24.04                |
| 실행      | 개발 명령                 | systemd                     |
| 외부 공개 | 로컬에서만 접근           | Nginx·HTTPS                 |
| 임시 파일 | OS 임시 디렉터리          | OS 임시 디렉터리            |

- 프런트엔드는 환경별 API 기준 주소만 바꾼다.
- 포트, 저장 경로, 작업 제한과 허용 Origin은 환경변수로 주입한다.
- 비밀번호, API 키와 Firebase 자격증명은 소스와 Git에 넣지 않는다.

## 서버 운영 결정

### 확인된 현재 상태

- 오라클 계정은 Free Tier이며 리전은 Japan East(Tokyo)다.
- 기존 `sarangbang-tts-bot` 서버는 `VM.Standard.E2.1.Micro` 1대이며 Always Free다.
- 기존 서버와 연결된 부트 볼륨은 47GB 1개다.
- 새 `VM.Standard.A1.Flex`의 Always Free 한도는 계정 전체 합계 2 OCPU·12GB다.
- 콘솔에서 A1 사용량은 CPU 0/2, 메모리 0/12GB로 확인했다.
- A1 2 OCPU·12GB 선택은 가능했지만 실제 인스턴스 생성은 하지 않았다.
- 2026-08-30에 2 OCPU·12GB와 1 OCPU·6GB 생성을 각각 시도했으나 Tokyo AD-1의
  `Out of capacity` 오류로 모두 실패했다.

### 목표 배치

```text
기존 E2 서버 (1GB)
├─ 현재 운영 서비스 유지
└─ 새 서버 안정화 전 복구 경로

로컬 Mac (ARM64, 우선 구현)
├─ media-analysis-service API
├─ 단일 분석 작업 큐와 Worker
├─ yt-dlp·FFmpeg·음악 분석 도구
└─ 자동 테스트와 실제 1곡 검증

새 범용 A1 서버 (2 OCPU·12GB, ARM64, 생성 대기)
├─ 검증된 media-analysis-service 배포
├─ 단일 분석 작업 큐와 Worker
├─ yt-dlp·FFmpeg·음악 분석 도구
└─ Nginx·HTTPS·systemd 운영
```

- 기존 E2 서버와 기존 서비스는 이번 구현에서 건드리지 않는다.
- 분석 서비스가 꺼져도 기존 YouTube 목록·재생·이어듣기는 계속 동작해야 한다.
- 서버 생성 전까지 로컬 API로 기능을 완성하고 실제 서버 코드에 별도 분기를 만들지 않는다.
- 서버 생성 후 소스, lockfile과 설정 예시를 배포하고 운영 환경변수만 별도로 주입한다.

### 비용 경계

- A1 총합 2 OCPU·12GB와 Always Free-eligible 사양을 유지한다.
- 기존 47GB에 새 기본 47GB를 추가하는 구성을 우선하고 불필요한 추가 볼륨·백업·유료
  성능 옵션을 켜지 않는다.
- 생성 직전 Always Free 표시, A1 사용량과 예상 비용을 다시 확인한다.
- 유료 계정 전환, 유료 사양, 추가 유료 저장공간은 이번 계획 범위가 아니다.

## 목표

- 노동요에 추가된 YouTube 곡을 오라클 서버에서 한 곡씩 분석한다.
- BPM, 조성, 비트·마디, 코드, 드럼 시작·종료와 곡 구간 후보를 만든다.
- 재생바 아래에서 분석 결과를 표시하고 사용자가 드래그로 수정할 수 있게 한다.
- 사용자 수정값을 우선해 두 곡의 드럼이 겹치지 않는 스마트 전환을 실행한다.


## 로컬 서비스 구조

```text
media-analysis-service/
├─ src/api/          요청 검증·응답
├─ src/jobs/         작업 상태·단일 큐
├─ src/media/        yt-dlp·FFmpeg 경계
├─ src/analysis/     BPM·비트·드럼·구간 알고리즘
├─ src/storage/      작업 결과·재시작 복구
├─ tests/            단위·통합 테스트
├─ scripts/          로컬 실행·Ubuntu 설치
└─ .env.example      비밀값 없는 설정 예시
```

- Python 기반 API와 분석 Worker로 시작한다.
- 첫 버전은 외부 Redis 없이 단일 프로세스 큐와 로컬 작업 DB로 단순하게 구성한다.
- API, 다운로드, 변환과 분석을 분리해 알고리즘 테스트가 네트워크에 의존하지 않게 한다.
- 임시 오디오는 작업별 디렉터리에 두고 성공·실패·중단 모두 정리한다.

## 최소 API 계약

- `POST /v1/jobs`: `videoId` 분석 요청, 작업 ID 반환
- `GET /v1/jobs/{jobId}`: 대기·실행·성공·실패 상태 확인
- `GET /v1/results/{videoId}`: 저장된 최신 자동 분석 결과 반환
- `DELETE /v1/jobs/{jobId}`: 대기 작업 취소와 임시 파일 정리
- `GET /health`: 프로세스, FFmpeg와 작업 큐 준비 상태 확인

- 임의 URL과 로컬 파일 경로는 받지 않고 초기 범위에서는 YouTube `videoId`만 허용한다.
- 같은 `videoId`의 동시 요청은 하나의 작업으로 합친다.
- 응답 스키마는 버전 필드와 분석기 버전을 포함한다.

## 데이터 계획

```text
users/{uid}/workmusicAnalysis/{videoId}
```

- URL은 저장하지 않고 `videoId`로 표준 YouTube URL을 복원한다.
- 자동 분석 `detected`와 사용자 수정 `manual`을 분리한다.
- 재분석은 `detected`만 교체하고 `manual`은 보존한다.
- 오디오 파일과 만료되는 스트림 URL은 저장하지 않는다.
- 같은 영상의 중복 분석을 줄이는 공통 캐시는 사용자별 저장 구현 후 검토한다.

## 스마트 DJ 계획

- BPM 차이, 조성, 에너지와 분석 신뢰도로 다음 곡 적합도를 계산한다.
- 미세 BPM 조절 대신 다음 공식으로 드럼이 겹치지 않게 한다.

```text
B곡 재생 시작 = A곡 드럼 종료 - B곡 드럼 시작
```

- B곡의 드럼 없는 인트로가 먼저 나오고 A곡 드럼 종료 시 B곡 드럼이 시작되게 한다.
- YouTube 버퍼링이나 대기 플레이어 실패 시 기존 고정 시간 이어듣기로 대체한다.

## 로컬 구현 순서 (완료)

1. `media-analysis-service` 프로젝트 뼈대, 규칙, 환경변수와 health check를 만든다.
2. 작업 상태 계약과 단일 큐를 구현하고 재시작·중복·취소 테스트를 만든다.
3. yt-dlp 다운로드와 FFmpeg PCM 변환을 독립 Adapter로 구현한다.
4. 고정된 짧은 오디오 fixture로 BPM·비트·마디 분석부터 구현한다.
5. 드럼 시작·종료와 구간 후보를 추가하고 신뢰도·분석기 버전을 반환한다.
6. 임시 파일 정리, 시간·크기 제한과 실패 응답을 검증한다.
7. 실제 YouTube 1곡을 수동 분석하고 원본·임시 파일이 남지 않는지 확인한다.
8. 마감이즈커밍에 API Client를 추가하고 로컬 주소로 작업 요청·상태 표시를 연결한다.
9. 가짜 데이터 기반 곡 지도 편집기와 자동·수동 값 분리를 구현한다.
10. 실제 재생과 분석 결과를 연결하되 분석 실패 시 기존 재생으로 복귀한다.

## 오라클 배포·전환 순서

1. 자동 재시도로 `bacbaqui-apps-a1` 생성 성공과 Always Free 사양을 확인한다.
2. Ubuntu 업데이트, Nginx, Git, FFmpeg, Python과 `/srv/apps`를 준비한다.
3. 로컬에서 통과한 소스와 lockfile을 `/srv/apps/media-analysis-service`에 배포한다.
4. 운영 환경변수, 전용 실행 계정과 systemd 서비스를 설정한다.
5. localhost health check와 고정 fixture 분석을 먼저 통과시킨다.
6. 임시 도메인에서 Nginx·HTTPS·인증·요청 제한을 검증한다.
7. 실제 YouTube 1곡을 분석하고 CPU·메모리·디스크·임시 파일을 확인한다.
8. 사용자 승인 후 프런트엔드 운영 API 주소만 오라클 주소로 전환한다.
9. 로컬과 운영의 동일 fixture 결과·오차 허용 범위를 비교한다.
10. 기존 E2 서버는 변경하지 않고 범용 A1 서버만 별도 운영한다.

## 승인 경계

- 문서 작성과 읽기 전용 조사는 별도 외부 변경 없이 진행할 수 있다.
- A1 인스턴스 생성은 이미 승인된 자동 재시도 범위에서만 수행한다.
- DNS와 외부 서비스 허용 주소 변경 전 영향 범위와 복구 방법을 보고하고 승인을 받는다.
- 기존 서버의 서비스와 데이터는 이번 범위에서 변경하지 않는다.

## 한계와 검증

- YouTube 임베드는 미세 속도 조절, 샘플 단위 비트 잠금, EQ와 스템 믹싱을 보장하지 않는다.
- 정적 검사와 별도로 실제 YouTube 준비·버퍼링·자동재생과 청각 QA가 필요하다.
- 서버의 YouTube 접근 안정성, 정책과 저작권 범위는 구현 시점에 다시 확인한다.
- A1 리전 가용 용량은 생성 시점에 부족할 수 있으므로 실제 생성 성공을 미리 보장하지 않는다.
- ARM64를 지원하지 않는 기존 바이너리·컨테이너는 대체 설치 또는 기존 서버 유지가 필요하다.
- macOS와 Ubuntu에서 FFmpeg·Python 분석 라이브러리 버전과 부동소수점 결과가 조금 다를 수
  있으므로 동일 fixture의 허용 오차를 테스트로 고정한다.
- DNS 전환, 실제 Firebase·YouTube·파일 처리와 청각 QA는 정적 검사와 별도로 수행한다.
