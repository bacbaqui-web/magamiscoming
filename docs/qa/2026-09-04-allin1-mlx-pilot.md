# All-In-One MLX 2곡 비교 시험

## 결론과 범위

후렴/벌스 라벨과 1절 종료 후보를 생성하는 데 유망하다. 2곡 모두 JSON 출력에 성공했지만 청취 정답 검증 없이 정확도 향상으로 단정하지 않는다. 운영 분석기, Oracle, 재생 로직, 수동값, 서버 DB는 변경하지 않았다. 전곡 분석은 하지 않았다.

## 환경

- Apple M4, RAM 16 GiB, macOS 26.5.1.
- 별도 Python 3.11.15 venv: `/tmp/workmusic-structure-xlmUh8/venv`.
- `all-in-one-mlx 1.0.6`, `demucs-mlx 1.4.6`, `mlx 0.31.2`.
- 모델 `harmonix-all`, 분리 seed 42, 앙상블/멀티프로세스 병렬 비활성, 디스크 중간 처리.
- MLX 캐시 128 MiB, 메모리 가이드라인 4 GiB. 이는 프로세스 전체의 강제 상한이 아니다.
- 입력은 같은 YouTube 영상의 오디오. 기존 분석기는 mono 22050 Hz PCM으로 변환해 실행하고 새 엔진은 원래 스테레오 WAV를 사용했다. 각 엔진의 입력 계약 차이이며 동일 PCM 입력 비교는 아니다.

## 결과

| 곡                                      | 길이    | 기존 후렴 결과  | 새 모델 첫 후렴 | 1절 종료 후보 | 새 실행 전체 시간 |
| --------------------------------------- | ------- | --------------- | --------------- | ------------- | ----------------- |
| Hvn High (`iMOkDVsABtI`)                | 3:14.32 | 없음, 일반 구간 | 1:13.47–1:31.75 | 1:31.75       | 36.24초           |
| Never Gonna Give You Up (`dQw4w9WgXcQ`) | 3:33.04 | 없음, 일반 구간 | 0:43.58–1:00.48 | 1:00.48       | 36.38초           |

두 곡 모두 첫 후렴 전에 verse를 반환했으므로 첫 후렴 끝을 제안한다. 도입부터 chorus인 곡에서 두 번째 후렴을 선택하는 규칙은 이번 표본으로 검증하지 못했다. 연속된 같은 chorus 라벨은 하나로 합쳐야 한다.

기존 서버 순수 분석 함수는 각각 0.132초/0.129초, 프로세스 누적 최대 RSS 약 45 MiB였다. 다운로드·변환·상세 파형 저장을 제외한 측정이다. 새 모델 전체 CLI 시간은 로딩·음원 분리·스펙트럼·구조 추론을 포함하며 다운로드/패키지 설치는 제외한다. 첫 성공 실행의 모델 다운로드/초기 캐시 비용 일부는 포함되므로 순수 추론 시간과 혼동하지 않는다. UI 대기열 체감 시간이나 정확한 배속 비교로 사용하지 않는다.

성공한 새 실행의 `/usr/bin/time -l`:

| 곡                      | 최대 RSS                   | peak memory footprint      |
| ----------------------- | -------------------------- | -------------------------- |
| Hvn High                | 3,964,108,800 B (3.69 GiB) | 6,535,449,696 B (6.09 GiB) |
| Never Gonna Give You Up | 4,655,841,280 B (4.34 GiB) | 7,423,380,672 B (6.91 GiB) |

Metal 통합 메모리 때문에 RSS만으로 전체 부담을 설명할 수 없다. 초기 기본 in-memory 실행은 footprint 13,664,849,472 B (12.73 GiB)에 달했다. 이 실행은 명시한 빈 weights 폴더로 인한 가중치 조회 오류로 실패했으며 성공 시간에 포함하지 않는다. 가중치는 기본 검증 다운로드 경로로 전환했다. 최초 설치에는 `demucs-mlx[convert]` 추가가 필요했다.

## 경계의 의미

- Hvn High: 기존 드럼 구간 0:08.32–3:10.92, 새 모델은 0:00.32부터 verse, 2:44.90부터 outro다. 음악적 intro/outro와 드럼 유무는 다른 기준이다.
- Never Gonna Give You Up: 기존 드럼 시작 0:00.032, 새 intro 끝 0:18.24. 마지막까지 chorus이며 별도 outro를 반환하지 않았다.
- 따라서 새 intro/outro를 초록 경계에 그대로 대입하면 '드럼이 겹치지 않게'라는 요구를 보장하지 못한다. 드럼 경계 검출과 구조 분류를 별도 정보로 유지해야 한다.
- 구간 시간 오름차순·연속성·양의 길이를 확인했다. 마지막 끝점은 모델 프레임 반올림 오차가 있어 실제 길이로 clamp해야 한다.
- 음원을 듣고 정답 라벨을 작성하거나 경계 오차를 측정하지 않았다. '후렴 후보를 출력했다'는 검증이지 정확도 점수는 아니다.

## 산출물과 다음 판단

- 원본 출력: `/tmp/workmusic-structure-xlmUh8/results/iMOkDVsABtI.json`, `dQw4w9WgXcQ.json`.
- 기존 비교 결과: 같은 폴더의 `*.baseline.json`; 상세 단계 시간: `timings.jsonl` (실패 실행 일부 기록도 포함).
- 재현 실행기: `run_mlx.py`, `baseline.py`. 임시 환경/입력은 약 1.2 GiB이며 아직 보관 중이다.
- 모델 캐시: `~/.cache/demucs-mlx` 약 160 MiB, `~/.cache/all-in-one-mlx/weights` 약 13 MiB, 추가 PyTorch 체크포인트 약 80 MiB. 패키지 캐시 용량은 별도다.
- 사용자가 위 첫 후렴 끝을 실제로 들어보고 1절 끝으로 맞는지 확인하는 것이 다음 단계다. 승인 없이 운영 교체/배포하지 않는다.
- MLX는 Apple Silicon용이므로 Oracle에 그대로 옮길 수 없다. 서버용 원본 엔진의 별도 성능·자원 검증이 필요하다.
